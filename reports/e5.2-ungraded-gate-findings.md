**Block 6.3** (course-closing reflection) had `threshold: 0` but no `confidenceFloor` override

Both mirror the exact merge path already in production for every other `reteach_gate` block in
this package (1.12, 2.10, etc.): `passingOverride` is the block's top-level legacy field, read
by `createAssessmentSession.ts:buildConfigSnapshot` (`teachBackBlock.passingOverride`, line 226)
— not the nested `assessment.passingOverride` — confirmed by reading `buildConfigSnapshot`
directly before authoring against it. `showScoreToLearner` comes from the *nested*
`assessment.showScoreToLearner`, merged via `mergeAssessmentConfig(assessment, block.assessment,
teachBackBlock.passingOverride)` (line 223-227) into `mergedAssessment.showScoreToLearner`
(`buildConfigSnapshot` line 243). Two different fields, two different sources — verified against
current code rather than assumed from precedent, since a earlier stage this session (Stage 1
Part 2 of the reteach-gate write path) found exactly this kind of "silently reads the wrong
field" gap once already.

`passingSchema.confidenceFloor` (`journey-package.schema.ts:295`) now carries a doc comment
recording the gotcha this stage exists to fix, so the next author/agent doesn't re-spend a full
investigation stage rediscovering it.

## Finding recorded, not fixed: closing-message framing

**`buildPassedClosingMessage`/`buildMaxTurnsClosingMessage`** (`buildAssessmentPrompt.ts:180-254`)
frame every `reteach_gate` closing message as assessment language, unconditionally:

- Passed path: "the student has demonstrated sufficient understanding... this is their moment
  of success."
- Max-turns path: "hasn't quite demonstrated full understanding yet, and that's completely
  okay... learning takes time."

`showScoreToLearner: false` suppresses the *numeric* score in both paths (confirmed by reading
the function bodies) — but does not touch this framing. For an ungraded reflection ("what
surprised you about AI," "revisit your career belief"), this language implies grading happened
when none did — a real, learner-visible mismatch, not a cosmetic one.

**This is reported as a missing config field, not a prompt bug.** `reteach_gate` currently has
exactly one closing-message shape (assessment framing) baked into a shared prompt builder used
by every `reteach_gate` block in the system — MI, PBJ, every other course's real graded gates,
plus now this course's two ungraded ones. The palette now has two legitimate uses for the same
mechanism (graded comprehension gates and ungraded multi-turn reflection), and only one of them
has a matching closing-message tone. The likely fix is a new config field (something like
`assessment.framing: "graded" | "reflection"`, defaulting to `"graded"` to preserve every
existing course's behavior) that `buildAssessmentPrompt.ts` branches on to select a different,
non-assessment-flavored prompt template for the reflection case.

**Not built in this stage, on explicit instruction**: `buildAssessmentPrompt.ts` is shared by
every `reteach_gate` session in the system, including MI and PBJ's live chat-surface gates —
changing it is well outside E.5.2's scope. Blocks 1.4 and 6.3 ship with the mismatched framing
as a known, reported limitation.
